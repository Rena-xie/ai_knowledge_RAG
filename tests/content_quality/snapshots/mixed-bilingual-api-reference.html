Bilingual API Reference 双语接口参考

这个接口参考说明知识检索服务的公开契约。调用方提交明确的问题， 服务返回证据列表、来源标识和稳定的错误码。接口不会生成自然语言答案， 也不会调用大型语言模型。

This API reference documents the public contract of the knowledge retrieval service. Clients submit an explicit question and receive evidence, source identifiers, scores, and stable error codes. The API does not generate answers or call a language model.

请求 / Request

请求体包含一个非空问题，长度限制为一千个字符。服务应在召回前完成 参数校验，失败时返回可以稳定识别的错误信息。

The request body contains one non-empty question with a maximum length of one thousand characters. Validation happens before retrieval, and failures return an error that clients can handle deterministically.

响应 / Response

  1. 证据正文与标题路径 Evidence text and heading path
  2. 来源 URL 与 child 标识 Source URL and child identifier
  3. 融合分数与实际检索路径 Fused score and retrieval path
POST /api/v1/search
Content-Type: application/json

{"question": "RAG 如何保存引用？"}
状态 / Status含义 / Meaning
200返回证据 / evidence returned
503检索不可用 / retrieval unavailable

所有证据必须保留原始语言。中文问题可以命中英文资料，英文问题也可以 命中中文资料，但响应不能伪造不存在的引用。

Every evidence item keeps the source language. Chinese questions can retrieve English passages, and English questions can retrieve Chinese passages, but responses must never invent citations.

验收说明 / Acceptance notes

接口测试需要同时检查成功响应、参数错误、检索不可用和安全异常。成功 响应应包含稳定的来源编号、切块编号、标题路径、正文和分数；参数错误 不应调用外部服务；检索不可用时应返回明确的状态码，并且不能泄露内部 路径或异常原文。中文、英文和双语页面必须分别验收，混合语言页面不能 被简单归入单一语言而失去可观察性。测试数据应使用隔离数据库和本地 快照，不能修改用户真实知识库，也不能依赖随机网络状态。只有独立诊断 命令可以访问公开页面，并把页面漂移与代码回归分开报告。

文档维护者应先检查清单中的来源和时间信息，再确认快照哈希没有变化。 如果真实页面发生更新，应重新保存快照并审查标注，而不是直接覆盖旧 基线。所有失败样本都要保留可复现证据，让后续修改能够比较修改前后的 指标变化，并确认没有牺牲已有语言或结构能力。
