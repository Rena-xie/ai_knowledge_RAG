双语知识库实践指南

这个实践指南说明如何建立同时支持中文和英文的知识库。系统保存原始来源、 正文快照和版本信息，并在检索时返回能够追溯的证据。知识库不生成答案， 只把相关片段交给上层代理处理。

This practical guide explains how to build a knowledge base that supports both Chinese and English documents. The service stores source metadata, content snapshots, and version information, then returns traceable evidence for downstream agents.

入库流程 / Ingestion workflow

  • 先验证 URL，再抓取最终页面并保存重定向别名。
  • Validate the final URL and preserve redirect aliases.
  • 解析正文、计算指纹，并拒绝完全重复的内容。
  • Extract content, compute fingerprints, and reject duplicates.

示例 / Example

async def ingest(url):
    document = await fetch_and_extract(url)
    return await store_document(document)

最后，在修改索引之前完成解析和切块校验。失败的刷新任务不得破坏已经 发布的正文与检索索引。系统应记录稳定错误码，方便代理和用户定位问题。

Finally, validate extraction and chunking before changing the index. A failed refresh must not damage published content or retrieval data. Stable error codes help the agent and the user diagnose failures.

质量检查 / Quality checks

每次更新解析器或调整清洗规则之后，都要重新运行冻结的正文质量集合。 检查报告需要分别给出中文、英文和双语页面的标题准确率、正文召回率、 噪声比例以及代码、列表和表格的保留情况。只要指标下降，就应查看具体 失败页面，确认是网站内容发生变化、人工标注需要更新，还是解析器出现了 回归。不能为了得到漂亮的数字而删除困难样本，也不能在失败时悄悄降低 验收门槛。真实线上页面用于单独诊断，冻结快照用于稳定回归，两种检查 必须保留清晰边界。
